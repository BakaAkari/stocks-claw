# stocks-claw 产品愿景

> 版本：v3.0（2026-07-22）
> 本文是产品北极星。当前实现、迁移路线和执行清单分别以 `ARCHITECTURE.md`、`PLAN.md`、`EXECUTION_PLAN.md` 为准。

## 1. 产品定位

stocks-claw 是为单一用户服务的 **个人投资分析师系统**。它不是自动交易系统，也不是把固定技术规则包装成唯一答案的量化策略。

系统由四个职责明确的参与方组成：

1. **确定性数据系统**：保存经用户确认的金融记忆，采集行情、历史价格、新闻、公告、宏观和事件，计算估值、技术特征、组合约束、流动性与数据质量。
2. **LLM 投资分析师**：读取统一证据快照，综合用户持仓、成本、风格、市场数据、新闻和规则候选，形成有立场、可解释、可验证的投资建议与市场研判。
3. **确定性风险与可执行性检查器**：检查建议是否引用真实证据、是否可交易、是否违反硬约束、金额和比例是否可行；它不替代分析师重新做投资判断。
4. **用户**：唯一决策人。用户决定执行、部分执行、拒绝或延后，系统不得自动下单。

## 2. 目标用户流程

### 2.1 金融记忆

```text
用户发送自然语言资产与偏好
→ LLM 提取结构化草稿
→ 系统与现有记录生成 diff 和不确定项
→ 用户确认
→ 原子写入账户、持仓和投资画像
```

任何长期金融记忆写入都必须经过用户确认。行情、新闻、推断和模型结论不得混入用户事实。

### 2.2 定时分析

```text
定时/事件触发
→ 统一采集新闻、公告、行情、历史、宏观和事件
→ 构建同一 as_of 的 UnifiedAnalysisSnapshot
→ 计算技术特征、轮动、组合暴露、风险与候选信号
→ LLM 生成结构化 InvestmentAdvisory
→ 确定性可执行性验证
→ 确定性渲染与推送
→ 用户反馈与后续复盘
```

### 2.3 最终交付

每份主窗口报告应回答：

1. 当下市场处于什么状态，最重要的驱动与冲突是什么；
2. 用户当前持仓应该买、卖、持有、等待还是换仓，幅度、条件和理由是什么；
3. 执行动作后组合、现金和风险如何变化；
4. 未来一至数周和一至三个月的主要情景、验证条件和证伪条件是什么；
5. 当前值得关注和布局的板块、资产类别和标的是什么，哪些只是研究候选；
6. 哪些数据不可靠，什么情况下必须暂停判断；
7. 下一次检查的时间、价格、事件或数据条件是什么。

观察窗口只报告相对上一主窗口的实质变化；无变化时保持静默。

## 3. 核心架构不变式

### 3.1 单一职责

- 数据系统提供事实、来源、时效、计算结果和硬约束。
- 规则引擎提供候选信号与风险证据，不拥有最终投资建议权。
- LLM 投资分析师拥有综合判断权，但不能修改事实或绕过硬约束。
- Validator 只做语义证据与可执行性检查，不得偷偷生成第三套投资建议。
- Renderer 只展示已经通过验证的结构化结果，不引入新事实和新数字。

### 3.2 单一语义权威

同一种约束只能有一个权威验证位置。上游拥有完整 evidence 时完成语义验证，下游通过版本、内容哈希和 validation receipt 验证完整性，不得用信息更少的规则重新猜测。

数字授权必须基于 `metric + value + unit + source/fact_ref`，不能用“其他字段碰巧出现相同数字”授权。

### 3.3 六层一致性

任何今日动作必须同时满足：

1. 数据支持分析；
2. 分析支持建议；
3. 建议符合资产属性；
4. 单资产建议符合组合目标；
5. 组合建议符合风险状态；
6. 报告符合交易窗口和实际可执行条件。

冲突无法裁决时必须交给用户，不得用默认规则伪装成唯一正确答案。

## 4. 能力域

1. **自然语言金融记忆**：资产、账户、成本、流动性、偏好和约束的确认式维护。
2. **统一市场证据**：新闻、公告、行情、历史、宏观、事件和来源质量的一致快照。
3. **专业综合分析**：技术、基本面、宏观、情报、组合和用户风格的统一判断。
4. **持仓与调仓建议**：动作、幅度、资金来源、执行条件、取消条件、结算与组合影响。
5. **机会发现**：持仓外板块、资产类别和标的的受控研究与布局候选。
6. **可问责预测**：条件、时限、置信度、证据和到期结算。
7. **主动节奏**：盘前、盘后、事件和异常驱动的有价值推送。
8. **反馈学习**：执行、拒绝和结果归因，校准用户风格与建议质量。

## 5. 永久边界

- 不自动下单，不连接券商执行交易。
- 不承诺收益，不把置信度表述为收益概率。
- 不让 LLM 直接写长期金融记忆。
- 不在缺失、过期或异常数据上伪造确定结论。
- 不把研究候选包装成已批准动作。
- 不为追求字段数量、报告长度或架构复杂度牺牲用户决策价值。

## 6. 成功标准

1. 用户可以自然语言维护资产和偏好，并清楚确认每次变更。
2. 每个分析窗口使用时间一致、来源可追踪的证据快照。
3. LLM 能综合所有证据给出明确、条件化、组合一致的建议，而不是拼接规则结论。
4. 所有建议通过确定性证据和可执行性检查，但检查器不重复投资判断。
5. 报告能稳定给出持仓动作、市场研判和机会候选，且不会因校验契约漂移误杀合法内容。
6. 建议、执行、拒绝和预测形成真实复盘闭环。
7. 用户持续确认系统减少了决策成本并改善了纪律。
