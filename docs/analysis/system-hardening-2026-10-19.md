# 系统健壮性审查与实施边界

2026-10-19。依据当前工作区代码、契约和隔离测试；不是 NAS、真实账户或在线模型验收。
本次没有声称逐行审计全仓。重点核查金融事实读取、Advisory 动作权威、调度、
展示/重发入口和现有测试的覆盖边界。当前动态进度统一看 `../../STATUS.md`。

## 判断

系统已有可复用的事实确认、对账、提案冻结、用户决定和逐笔成交基础。
当前最大问题不是缺少更多指标，而是部分边界只在文档中成立、尚未贯穿到最终入口，
以及动作校验支持的业务子集远小于产品设想。应先修这些边界，再扩大可建议范围。

“完整”至少要求：确认事实不被分析改写；每个建议可重建其输入和校验依据；
失败能解释；买入、持有、退出各有完整流程；真实账户与部署分别验收。
仅让 buy/add 通过、增加测试数量或完成重构均不能满足这些条件。

## 本轮实际闭合的边界

1. 分析历史读取不再调用预测结算器或保存预测；缓存和分析 artifact 仍可写。
2. 现有四主窗口的报告 CLI 必须有 Advisory 来源。旧无来源 artifact 仅可由离线
   渲染函数作兼容分析，不可经报告 CLI 交付。
3. 验证 snapshot、receipt、原始提案、最终决定、展示快照及其来源 ID/哈希。
   缺失、改写、跨会话错配、重复/遗漏展示动作均拒绝。
4. cron 使用的 `run_llm_report.py` 对主窗口不再做第二次自由文本改写。
   `--force-llm` 不再绕过主窗口时效；它仅保留情报窗口的历史重发语义。
5. 最终文字校验通过后才写报告 payload。模拟 smoke 延伸到确定性报告校验，
   不再在“保存了 lineage”处结束。

内容哈希只是完整性检查，不是数字签名、用户授权或部署许可；有权限整体替换 artifact
的人仍能重算哈希。文件权限、生产路径、发布提交和备份恢复须由运维阶段覆盖。

## 后续实施顺序与验收

### 1. 真实账户只读就绪与证据时点

需要用户提供并确认账户事实，不能拿模拟数据代替。先输出支持的导入模板、歧义清单、
字段差异与核对报告，再在用户确认后录入。账户、币种、单位、可用数量和可用现金分别核对。
分析前后对金融事实目录做内容比对，证明包括历史读取在内的全路径不改事实。

HARDEN-02 已实现 CLI/MCP 只读预检、当前事实就绪检查、空模板和隔离烟测。
`_snapshot_too_old` 已拒绝无效和超前超过 60 秒的时间；`_build_macro_facts`
逐字段保留来源 `as_of`，缺失保持未知。反例测试通过；真实账户核对与确认仍待用户资料。
这些完成项不解除费用预算或组合投影阻断。

### 2. 买方费用预算

HARDEN-03 已实现独立的用户确认预算契约，声明账户、标的、币种、适用市场、有效时点、
数量/本金上限、费用上界和来源。已有持仓 add 支持含费现金校验和快照冻结，
同账户同币种多笔买入仍阻断；真实费用待用户确认。
校验购入金额加费用不超过确认可用现金；不能默认为零费用、使用未结算卖出收入，
或让 LLM 提供“确认预算”。已测试现金不足、币种不符、预算失效、撤销与成功路径，并验证报告费用展示和交付到期阻断。
新标的买入与已有持仓加仓必须分别定义身份/账户路由，不能把 buy 当作 add 的别名。

### 3. 组合约束投影

在统一、可追溯的估值和 FX 输入上，计算整批提案后的账户现金、持仓、隔离池和分桶权重。
不得逐条通过而整体超限，不得跨账户借钱，不得对多币种直接求和。
减仓不一定改善所有约束，不能为卖出统一豁免。保留原提案和拒绝原因，不自动缩量改方向。
验证通过才替换当前 `allocation_constraints_require_portfolio_projection` 阻断。

### 4. 候选—持有—退出的用户流程

将 `research_candidate/core_candidate/core_hold/tactical_candidate/hold_review/exit_review`
落实成明确数据与迁移规则。用户确认角色、账户和 thesis 后才能晋级；低置信度或只有
一个技术指标的候选仍为研究。冻结原 thesis，后续证据追加；普通波动不自动触发卖出。
用 A 股和 IBKR 模拟场景分别走完入选、拒绝/晋级、成交、持有、退出复核与用户决定。

### 5. 运行与交付验收

按 Operating Model 的 L2→L3→L4→L5 顺序推进。明确允许的运行模式、部署提交、隔离目录、
是否允许推送及允许范围；默认阻断未经批准的生产交付。验证超时、重复任务、部分失败、
磁盘写失败、恢复/回滚、跨市场日历和时区。在线模型试运行需另有来源覆盖和人工纠错记录。
本轮没有修改 cron、连接 NAS、发送消息或提供部署许可。

### 6. 效果和维护性

先测事实覆盖、时效、错误可行性判断、用户纠错率和复盘完成率，再研究投资结果。
逐步消除按账户名猜测资产分类、重复展示映射和大型编排函数；以主链回归为边界拆分，
不为多用户抽象重写单用户产品。旧反馈不能因重构完成而自动恢复。

## 验证边界

本次隔离测试使用临时目录、模拟账户/报价/模型响应，真实运行生产内部代码。
这证明机制行为，不证明券商记录真实性、在线模型判断质量或未来收益。
仓库原有 39 条 Ruff 诊断分布在 13 个本轮未改文件，另列维护事项，未为了全绿而
扩大本轮修改；具体测试和 smoke 结果记录在 STATUS。
