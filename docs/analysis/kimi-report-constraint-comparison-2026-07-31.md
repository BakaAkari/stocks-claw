# 外部 AI 配置报告 vs stocks-claw 能力对照分析（2026-07-31）

> 对照对象：一份由通用 AI 助手（Kimi Chat）一次性生成的《个人资产配置
> 修正报告（硬约束版）》，原件含个人资产明细，**仅存于本地**
> `.local/个人资产配置修正报告_硬约束版_20260731.md`（已被 .gitignore
> 排除），不进入版本库。本文只保留抽象后的需求与结论，不含任何真实
> 持仓金额。

## 1. 背景

用户在 2026-07-31 让通用 AI 助手基于其完整持仓与两条硬约束生成了一份
资产配置修正报告，随后要求评估 stocks-claw 能否超越该类报告。本文是
评估结论的存档，也是 `docs/tasks/TASK-M4-constraint-model-upgrade.md`
的需求依据。

## 2. 外部报告的真实成色（投资交易分析师视角）

### 2.1 值得系统学习的优点

1. **硬约束建模是全文灵魂。** 两条用户硬约束——
   - 某类 QDII 基金平台限购（每日极小额度），卖出后事实上无法买回，
     卖出 = 不可逆退出该类敞口；
   - 海外券商账户资金受外汇管制，无法回流，与国内资金形成**封闭独立池**。
   报告据此把原建议逐一反转（止盈 → 持有 + 硬上限；统一再平衡 → 分池
   独立风控）。这是把**约束置于信号之上**的配置级决策结构。
2. **多期执行路径**：把建仓拆成 6 个月的 glide path，逐月给出金额、
   标的与资金来源，而非单次快照式建议。
3. **决策对照表**：每个修正都有"原建议 / 修正后 / 修正原因"三列对照。
4. **一致性检查**：逐条对照用户画像（左侧交易、易冲动、无法盯盘、
   偏好指数化）验证方案对齐。
5. **诚实声明**：主动披露被动决策（"持有不是看好，是无法买回"）与
   数据黑箱（某大额资产 IRR 未知）。

### 2.2 对抗式审查发现的缺陷

1. **伪精确胜率**：55%–95% 的"胜率"无方法论、无出处，报告自承是
   "经验估计"。极小金额的清仓决策也被标上 95% 胜率——决策量级与
   精度声明不匹配。这类数字放进 stocks-claw 的 E1 truth gate 会被
   直接拦截。
2. **估值数据无源无日期**：CAPE 分位、PE 分位、股息率、拥挤度等关键
   判断依据均无 `source_refs` 与新鲜度标记，错了无从审计。
3. **一次性快照，无闭环**：定投是否执行、硬上限是否触发、待确认事项
   是否完成，全部依赖用户自觉；报告本身不产生任何后续检查机制。
4. 口径瑕疵：胜率矩阵中"持有不动"标 N/A 却给出浮亏数字；个别大额
   资产的池别归类可争议。

## 3. stocks-claw 现状对照（系统设计师视角）

### 3.1 当前生产能力的实证状态

以 2026-07-31 最近一次真实推送产物为证：报告处于 `manual_review`，
可执行动作为空，用户可见文本中仍泄漏 `no settlement rule matched`
机器码（见 `docs/analysis/system-consistency-review-2026-07-30.md`
P1-5）。按 STATUS.md 的 VISION §2.3 评分：七问覆盖 2 全 / 2 半 / 3 缺，
走势研判、情景推演、提前布局三个板块缺失。

**结论：当前推送报告在信息密度与决策深度上明显不如外部报告。**

### 3.2 stocks-claw 已有、外部一次性报告不可能有的能力

1. **可信数字管道**：E1 truth gate + `validate_push_truth` 强制每个
   数字溯源到 artifact——恰好克制外部报告最大的病（伪精确 + 无源估值）。
2. **持续运转**：定时会话 + window delta + 下一检查点，是流水线而非
   快照。
3. **确认后写入的金融记忆**：建议 / 执行 / 预测持久化，为 M3 反馈
   闭环（"上次建议执行了吗"）提供地基。
4. **配置化约束与阈值**：2026-07-31 完成的去硬编码（`1ab7dec` /
   `7a60aac` / `03ee449`）把信号阈值、映射表、provider 端点、会话
   参数全部移入 engine.yaml / scheduled_sessions.json，经逐项新旧值
   对比确认行为保持（详见 STATUS.md 验证记录）。

### 3.3 关键能力空档（本分析的核心结论）

外部报告展示的**约束驱动配置级决策**，当前约束模型表达不了：
`stocks/config/portfolio_constraints.json` 只有权益/固收/现金/黄金
四桶 min/max 比例，无法表达：

1. **不可逆性**：限购 / 封闭期导致的"卖出后无法买回"，要求卖出建议
   必须携带不可逆警告，并改变裁决方向（止盈 → 持有 + 硬上限）。
2. **分池语义**：国内外汇管制形成的封闭池，要求资金分配建议永不跨池
   调配，且每桶独立风控。
3. **硬上限触发器**：超上限**必须减仓**（must-reduce），而非软比例
   提示。

此外，外部报告的"6 个月分批建仓 glide path"属于跨会话多期规划，
依赖 M3 反馈数据成熟后才具备意义，**不在** M4 范围内（见任务文件
非目标）。

## 4. 结论与行动

- 今天 stocks-claw 不能超越该类外部报告；M1 + M2 落地后可在**数字
  可信度与持续跟踪**两个维度超越，但**战略约束表达能力**需要专门
  补齐。
- 行动：新增 `docs/tasks/TASK-M4-constraint-model-upgrade.md`，将
  不可逆性、分池、硬上限三类约束语义纳入配置模型与裁决器，排入
  backlog（M1 关闭后重估排序）。
