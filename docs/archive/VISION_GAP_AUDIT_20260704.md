## 1. V1 认识复合型资产 — ❌

你要求的三层粒度,对照现状:

| 你要的粒度 | 现状 | 证据 |
|---|---|---|
| 锁定资产(保险)= 固定资金,不参与调仓 | `tradable` 字段存在但**没有任何消费方**:advice actions 校验只查 target 是否存在于持仓/watchlist/bucket,不查可动性;`locked_assets_present` 靠 asset_type 关键词("保险"/"锁定")猜测 | scaffolds.py 关键词表;S1-2 完成记录的校验逻辑 |
| 基金/理财 = 按板块大类管理 | 无板块概念。`asset_type` 自由文本进关键词分桶,"QDII/固收+/贵金属"全部映射失败;基金与任何市场数据零关联 | scaffolds.py `_map_asset_type` |
| 股票/证券 = 单支明细 | 已有 `instrument_key + quantity`(S1-1),但**无成本价**——只有半个明细 | models.py `FinancialAsset` |

这一条就是我们前几轮讨论的全部内容,S2 任务卡(Account/Position/classification/

## 2. V2 新闻 + 历史数据 → 提前布局 — ⚠️ 生产线在,传动轴断

**已建成的(质量相当高)**:
- 历史数据层:37 标的日 K 双源降级(A股东财→腾讯、美股 Nasdaq→Yahoo、crypto Binance)、90 天缓存、逐源降级记录;
- 信号层:`action_signals.py` 七态规则信号,每条附可复核的指标事实,阈值集中定义;`rotation.py` 5/20 日相对强弱排名;
- 事件层:官方日程 + Finnhub 财报日历 → `upcoming_events`,T+3 催化剂给信号叠加 `event_watch`;
- 新闻层:RSS + SEC EDGAR/巨潮一手公告 + 持仓定向 scope,`MarketEvent` 规则提取带 `matched_holdings`;
- prompt 契约:强制三分支情景树、触发条件必须可验证、禁止无条件"观察"——这份 prompt 是全项目最接近"专业分析师"形态的资产。

**断裂点:整条生产线运行在 watchlist 宇宙,不是你的资产宇宙。**

1. `action_signals` 与 `rotation` 的输入是 watchlist + 扫描池(`compute_action_signals(instruments=watchlist...)`)。你持有的标的若不在 watchlist,**没有信号、没有轮动排名、没有事件叠加**。持仓与 watchlist 之间没有一致性保证——S1-1 只做了"已映射资产与行情按 key 关联"的展示层标注。
2. 信号不知道你的仓位。`reduce_risk` 对一个你持有 90 股浮亏 350 刀的 XLE 和一个你完全没有的标的,输出完全一样;prompt 只能靠 LLM 自己把两张表对起来。
3. **基金/理财层完全在生产线之外**。你约 40-45 万的场外基金(纳指 QDII、黄金联接、固收+)没有 instrument_key、没有代理行情、不进任何信号/轮动/事件路径——而这是你资产里第二大的可调仓层。愿景说"基金按板块大类指导",现状是这一层连"板块"都不存在。

## 3. V3 止盈止损提醒 — ❌ 两条腿都缺

**断裂 A:没有成本价,"止盈/止损"在结构上不可表达。**
- `FinancialAsset` 无 cost_basis(S2 已设计);
- 更深一层:`AdviceRecord.triggers` 的类型只有 `price_above / price_below /
  pct_change_above / pct_change_below`,其中 pct_change 的基准是**建议日**,不是**你的成本**(models.py `_ADVICE_TRIGGER_TYPES` 与 DATA_MODEL "建议日以来累计涨跌幅")。也就是说,即使 S2 落地了成本价,现有触发器语法仍然写不出"XLE 回到成本价减半仓"或"浮盈超 20% 止盈一半"——这是 S2 任务卡也没覆盖的缺口,需补触发器类型(见 §6.2)。
- prompt 明令"禁止编造…成本"——正确的诚实纪律,但意味着当班分析师**永远无法**给出基于你真实盈亏的止盈止损线。

**断裂 B:没有"提醒",只有"下次问的时候告诉你"。**
- 触发核对(`advice_review`)只在 `build_context` 时运行——**pull 模式**:你不来问,触发器命中了也没人知道;
- VISION 六能力域的"主动节奏"(触发命中推送、定期简报)在 PLAN §4 明确标注**未立项**,候选队列里"定时扫描与触发推送(pull→push)"禁止开工;
- 仓库有 docker-compose/NAS 部署残留(docs/archive/NAS_DEPLOYMENT.md),但无任何 cron/调度/推送代码。

愿景说"达到指标后提醒用户",现状是:指标核对逻辑存在且诚实(fired/not_fired/no_data 只陈述事实),但既没有以你的成本为基准的指标,也没有"提醒"这个动作本身。

## 4. V4 信息搜索能力 — ⚠️ 面广,但边界同 V2

RSS 多源 + Google News 按 watchlist 动态模板 + SEC/巨潮一手公告 + Finnhub 财报日历,对一个本地系统来说覆盖相当好。但:一手公告和定向新闻**只查询 watchlist**(ARCHITECTURE §providers),同样不保证覆盖你的实际持仓;基金层(QDII 溢价、限购、汇率折算)没有任何信息源。"极强的信息搜索能力"里真正强的部分其实在系统外——你的 Agent(LLM)自带搜索,系统的职责是把资产结构和数据边界喂清楚,这个定位 VISION 已经写对了。

## 5. V5 专业可问责的建议 — ✅ 最完整

建议闭环(S1-1~S1-5 全部完成,460 tests):AdviceRecord(方向+actions+触发器)→ 确认保存 → 执行记录四态对照 → 预测台账到期结算 → 【复盘】四段注入下期上下文;样本 <10 不许说命中率;完成记录带 grep 行号级证据。这套问责纪律超过多数商业产品,是项目最值钱的存量资产。**它缺的只是上游原料**:建议落在没有成本、没有流动性分层、与信号脱钩的资产模型上,"专业"的上限被入口数据卡死——这正是你发起本轮讨论的直觉,审计确认这个直觉是对的。

## 6. 审计导出的增量设计(超出 S2 现有任务卡的部分)

### 6.1 三层管理粒度作为一等概念(呼应你的"不要严格按我说的做")

你的三分法(锁定/大类/单支)本质是**建议粒度**,我建议不要做成资产类型的硬编码,而是从 S2 的字段推导出一个派生字段 `advice_granularity`:

- `detailed`:有 instrument_key + quantity(+cost_basis 更佳)→ 单支级建议、价格触发器、止盈止损线;
- `sector`:无实时可交易性但有明确暴露(基金/理财,exposure_tags 齐)→ 只接受"层级"建议(加/减某暴露层),触发器挂在**代理标的**上;
- `fixed`:rebalance_eligible=false(保险/锁仓黄金)→ 只计入净值与流动性视图,建议引擎不得触碰。

推导而非录入的好处:用户补一个字段(比如基金代码),资产自动从 sector 升级到 detailed,不需要改分类。

### 6.2 代理标的映射(解决基金层脱离生产线)

给 exposure_tag 建一张小配置表 `exposure_proxy.json`:`nasdaq100 → us:QQQ`、`gold → a:518880 或 us:GLD`、`csi300 → a:510300`…… 场外基金虽无实时行情,但其暴露层的信号/轮动/事件可以通过代理标的流入:"纳指 QDII 层"就能收到 QQQ 的 reduce_risk 信号和财报季催化剂,prompt 里的"基金按板块大类指导"就有了数据支点。实现成本极低(watchlist 里 QQQ/GLD 等大多已在)。

### 6.3 成本基准触发器(解决止盈止损不可表达)

`_ADVICE_TRIGGER_TYPES` 增两类:`pnl_pct_above / pnl_pct_below`(基准 = position.cost_basis,依赖 S2);`advice_review` 核对时从持仓取成本计算。这样"浮盈 20% 止盈一半、回到成本价清仓"才能成为机器可核对的触发器,而不是留在 LLM 长文里的一句话。

### 6.4 持仓⊆watchlist 一致性守门

build_context 时确定性检查:每个 detailed 持仓的 instrument_key 必须在行情宇宙内,不在则自动加入本次请求或在 data_quality 显式报缺(S2-5 已含告警,建议升级为自动纳入)。

### 6.5 主动提醒 = 独立切片(现有排期纪律下的正确位置)

pull→push 是愿景 V3 的另一半,但它不依赖数据模型,依赖调度(cron + 通知通道)。建议保持它在候选队列,S2 落地后作为"切片 3"立项——那时触发器才有成本基准,提醒的内容才值得推送。**顺序必须是 S2 → 触发器扩展 → 推送**;先做推送只会把"与你仓位无关的信号"更频繁地打扰你。

## 7. 总评

| 层 | 成熟度 | 说明 |
|---|---|---|
| 数据可信底盘(行情/历史/新闻/事件/质量溯源) | ★★★★☆ | 双源降级+诚实报缺,超出个人项目平均水准 |
| 分析生产线(指标/信号/轮动/情景 prompt) | ★★★★☆ | 规则可复核,prompt 契约优秀 |
| 问责闭环(建议/执行/预测/复盘) | ★★★★☆ | 完整且有证据纪律 |
| **资产认知(愿景核心入口)** | ★☆☆☆☆ | 扁平列表+关键词分桶+无成本,三层粒度不存在 |
| **止盈止损能力** | ☆☆☆☆☆ | 成本基准与触发器语法双缺 |
| **主动提醒** | ☆☆☆☆☆ | 纯 pull,未立项 |

系统像一位**装备精良但从没见过你账本的分析师**:市场看得很清楚,说话有纪律、可问责,但因为不知道你每笔仓位的成本、不知道哪些钱动不了、不认识你近一半的资产(基金/理财层),它给出的只能是"对市场的判断",而非"对你的指导"。愿景的缺口不在分析能力,全部集中在**用户数据入口**——这与我们前几轮的结论互相印证,且本轮审计新增了两个此前设计未覆盖的必要件:**成本基准触发器(§6.3)与代理标的映射(§6.2)**,建议并入 S2 任务卡(或作为 S2 的兄弟任务),否则 S2 落地后"止盈止损提醒"仍然差最后一公里。
