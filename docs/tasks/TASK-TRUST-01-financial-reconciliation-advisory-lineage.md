## 价值顺序与本轮边界

1. 用户目标、资金用途、承受损失能力、期限、流动性需求和操作频率前置；未知显式。
   明确偏好与硬约束，不从历史操作或提示词替用户确认风格。
2. 显式确认的时点账户/持仓/现金快照 + 真实逐笔成交 + 非交易现金变动，推导期末
   数量和现金，与独立确认的期末记录核对。差异和证据缺失保留，不自动改账户事实。
3. LLM 获取同一份事实/约束，保留输入、提示词/模型来源、原始建议和验证结果；
   规则候选与 LLM 建议可辨认，拒绝原因可追踪，不把丢弃或替换建议当已接通。

没有用户提供的真实对账单或成交，本轮不伪造实际用户核对通过。测试/烟测在新临时
数据目录运行当前代码，显式标为模拟数据；不创建项目副本，不操作实际金融记忆。
不扩展胜率、净收益、回撤或策略自动调参，不恢复 cron，不提交推送或部署。

## 最小核对契约

- 对账输入有稳定 ID、实际时点、记录时点、来源及完整范围声明。账户/币种不能混并。
  现有资产估值不是现金余额，旧 quantity 无时点时不能默认成为对账基线。
- 成交允许用户自主交易，不强迫先伪造系统建议。明确账户、标的、单位、方向、数量、
  价格、费用和实际时间；与已有建议关联时继续严格验证来源。
- 非交易现金流独立登记，不能用调增余额掩盖缺成交。交易日账与已结算现金口径
  不混用；缺结算时点或费用时明确不可核对，不套用默认 T+1 或默认零费用。
- 计算采用确定性金额算术。opening + 全量区间变动 = expected closing，独立 closing
  是 observed；结果包含差额、使用记录 ID/hash、范围和缺口。
- 相同 ID 同内容幂等，冲突拒绝；未确认零写入。核对报告不自动写回持仓/余额。
- 对账一致只证明所提供记录在声明范围内一致，不证明没有遗漏交易或对账单真实性。

## LLM 责任链与验收

- 用户个人约束实际进入统一证据，保留版本/hash；不能只在文档中声明个性化。
- 去除固定用户风格提示；由用户确认的 profile/mandate 驱动，未知时如实记录。
- 原始 LLM 提案、模型/提示词来源、引用证据、验证回执和最终投影可追溯；规则提案
  不冒充 LLM 建议，模拟模型响应不冒充真实在线模型验收。
- 未知证据引用、资金/数量无法验证、硬约束冲突要阻断或转待复核；不能默默修饰成
  另一条建议。完整投顾动作权威的迁移程度必须按实际代码单独说明。
- 没有安全可用的真实 LLM 接口时保留代码和确定性集成证据，明确真实模型验收缺口；
  不读取凭据文件或把未配置的模型标为成功。
