# stocks-claw 最终对抗性交易系统审查

> 日期：2026-07-15
> 审查基线：`10f5e05`
> 性质：现行系统审查与后续验收基准
> 证据范围：当前代码、配置、Git 提交、最新 A 股/美股/情报定时产物、历史因子回测、全量测试与静态检查

## 1. 执行摘要

stocks-claw 已经不是行情脚本或简单 LLM 报告生成器。它具备多源行情与降级、持仓估值、技术规则、情报分析、因子裁决、产品类型路由、组合约束、资金分配、定时 Artifact 和 Agent 二次表达能力。

但系统目前仍应定位为：

- 合格的风险监控与交易研究工作台
- 有潜力的私人投资分析师助手
- 尚未通过实盘决策验收的规则引擎

当前不应定位为自动交易系统、已验证的量化策略、可以直接照单执行的组合管理系统或能稳定产生超额收益的私人基金经理。

核心判断：系统已经能发现大量局部问题，但尚不能稳定地在冲突信息中形成唯一、可执行、组合一致且可事后问责的最终决策。当前主要风险不是单个函数错误，而是局部合理、全局失配。

综合评分：

- 数据治理：7/10
- 风险发现能力：7/10
- 持仓事实整理：7/10
- 信号解释性：7/10
- 交易动作质量：4/10
- 组合配置能力：4/10
- 报告决策价值：5/10
- 实盘反馈闭环：2/10
- 整体成熟度：5.5/10

## 2. 审查方法：六层一致性原理

本次审查不以代码按设计运行为通过标准，而以真实交易决策是否闭环为标准。一条建议只有同时满足以下六层一致性，才有资格进入用户的今日行动清单：

1. 数据支持信号
2. 信号支持动作
3. 动作符合资产属性
4. 单资产动作符合组合目标
5. 组合建议符合风险状态
6. 报告符合当前交易窗口与可执行条件

系统当前在数据溯源、信号解释和部分资产路由方面已有良好基础，但在组合裁决、风险生命周期、窗口差异化和执行反馈方面仍存在系统性断裂。

## 4. 数据与信号一致性

### 4.1 已有优势

- 行情、新闻、宏观、基金净值和持仓估值均有来源或降级信息
- 能区分实时行情、T-1 基金净值和手工估值
- Provider 有主备链、错误分层和降级记录
- Artifact 保留足够多的事实用于事后审计
- 缺失数据不会统一伪装为正常值

### 4.2 全局新鲜度污染局部数据

`build_scheduled_run()` 当前从 `data_quality.quotes.freshness` 读取一个全局行情新鲜度，并传给全部持仓的 `finalize_decision()`。

真实产物中 A 股行情为当日盘中数据，美股行情为前一交易日收盘数据；全局 freshness 因美股而为 `stale`，A 股 Action Card 也被统一执行 `ratio × 0.5`。一个市场的时钟不应污染另一个市场的动作比例。

目标模型应为：每个持仓独立的 `price_as_of`、每张 Action Card 独立的 `market_freshness`、技术指标独立的 `indicator_as_of`、情报独立的 `intelligence_as_of`、基金净值独立的 `nav_as_of`。

### 4.3 数据异常没有先于交易规则

最新产物出现半导体 ETF 现价约 1.25、MA20 约 2.08、偏离约 40%。对正常 ETF 而言，这优先指向复权口径不一致、份额变化、价格源口径差异、Symbol 映射或缓存污染。

系统当前直接将其解释为强趋势破坏并输出减仓。正确顺序应为：命中异常阈值 → 标记 `data_anomaly` → 阻断技术动作 → 请求数据核验 → 核验通过后才生成交易建议。

## 5. 信号与动作一致性

### 5.1 Action Card 已真实进入决策链

当前路径为：

`QuantActionEngine.review_position()` → `collect_votes()` → `adjudicate()` → `finalize_decision()` → `action_cards`

技术信号、数据新鲜度、组合约束、事件和情报会实际修改最终 `signal` 或 `ratio`，并在 facts 中记录信号链。该设计优于让 LLM 自由生成比例。

### 5.2 `trend_confirm_days` 与交易含义不一致

参数名和文档语义表示连续 N 个交易日确认趋势破坏。但代码没有保存连续天数状态，而是按照 N 值收紧单日 MA20 偏离阈值。因此 `trend_confirm_days=3` 的真实行为是单日跌得更深才触发，不是连续三天确认。

必须实现真正的连续交易日状态，或重命名为额外偏离过滤参数，并修改全部文档与报告措辞。

### 5.3 `add_ladder` 与文档语义不一致

文档曾描述按持仓 PnL 深度选择加仓档位，代码实际按价格相对 MA20 的偏离程度选档。两者分别代表持仓管理与市场位置管理，不能混用。

当前同一个 MA20 偏离既参与是否触发，又参与加仓规模，风险维度过于同源。更稳健的档位应同时考虑 MA20 偏离、当前 PnL、当前仓位、波动率、情报冲突和组合约束空间。

### 5.4 情报覆盖率不等于有效信息覆盖率

`10f5e05` 修复了情报信号截断、缺失 symbol 和分类部分覆盖问题。最终 15 个活跃持仓均可得到 intelligence driver，字段覆盖结论成立。

但最新 18 条情报信号中，多数为程序补齐的 category-level `hold`。它们主要表达没有直接利空，不是独立资产级研究结论。

后续必须分别统计字段覆盖率、有证据的持仓匹配率、有方向的信号覆盖率、独立事件覆盖率和 synthesized fallback 占比。真实 LLM 信号、代理映射和分类补齐必须有明确 provenance 字段。

### 5.5 Driver、Conflict 和 Dissent 不一致

`_build_drivers()` 支持 exact、suffix、proxy、exposure tag 和 rationale 文本匹配；`IntelConflictRule` 只使用 instrument 后缀和 proxy。结果可能是 Driver 显示情报已匹配，但 Conflict Rule 认为没有匹配，`intelligence_conflict=none`。

同时 EventClusterRule 可以在 facts 中写情报利好与减仓矛盾，但因为 vote 方向被视为 neutral，`dissent` 仍为 null。Driver、Conflict、Dissent 必须消费同一个标准化匹配结果。

## 6. 动作与资产属性一致性

系统已区分场内证券、QDII、主动基金、固收+、贵金属、银行理财、现金和保险，并设置 full、fund、precious、info_only、skip 路由，该方向应保留。

但场外基金当前主要增加 T+2、净值确认和较高阈值，核心仍是 PnL 触发的机械止盈。长期 QDII、联接基金和主动基金应更多依据组合目标权重、估值极端程度、风格漂移、替代方向、申赎成本和核心仓或战术仓属性。

黄金同时存在组合超配、宏观利好、建行黄金大幅浮亏，以及 NEM、黄金联接、积存金三种不同风险属性。专业决策需要回答应减少哪一种黄金暴露，而不是只输出黄金总 Bucket 超配。

## 7. 单资产动作与组合目标一致性

### 7.1 权益低配与权益减仓同时发生

最新产物显示权益占比约 16%，低于 25% 下限；黄金占比约 16.7%，高于 15% 上限。同时输出科创 50、ITA、两只纳指 QDII、主动权益基金和半导体的减仓或止盈。

权益低配不代表弱势权益不能卖，但必须形成换仓链：卖什么、回收多少、买什么替代、何时买、换仓后比例，以及未成交时的风险处理。当前 capital allocation 只检测到冲突，没有完成裁决。

### 7.2 “净可动用约 101 万”具有误导性

真实流动性结构约为：现金或 T0 38.6 万，T1/T2 和大量现有持仓 62.9 万，锁定或不合格资产 54.1 万。

当前系统把现金、SGOV、股票 ETF、场外基金和黄金账户等 T1/T2 资产全部计入 deployable，最终报告约 101 万净可动用。从交易执行角度它们不是今日现金。

必须拆分为即时现金、今日卖出可回收、T+1 可用、T+2 或净值确认后可用、需要战略退出才能释放、不建议动用和锁定资产。在完成拆分前，`net_deployable_cny` 不应被 Agent 表述为今天可投入的现金。

### 7.3 Capital Allocation 不应修改 Action Card

`_build_capital_allocation()` 在加仓金额低于 800 元时，直接把传入 card 的 signal、ratio 和 action 改为 hold。Action Card 应是资产级判断；Capital Allocation 应输出 portfolio approval 或 execution suppression，而不应重写原始信号。

建议拆为 `raw_action`、`portfolio_approved_action`、`execution_status` 和 `suppression_reason`。

## 8. 组合建议与风险状态一致性

最新风险边界为 `level=hedge`、地缘政治 critical、暂停全部加仓、现金目标 15%。同一报告又要求给出至少三个未来方向、明确回答今天钱往哪放、展示轮动候选并处理权益低配。

必须明确优先级：风险硬约束 → 数据异常和新鲜度 → 止损纪律 → 组合约束 → 换仓与资金部署 → 研究候选。当 `suspend_accumulation=true` 时，资金部署段只能回答现金如何保持、哪些减仓可以执行、解除暂停的条件，不得生成即时买入方向。

多数最新 session 都为 critical，多个窗口均 push_now。Critical 状态必须增加首次触发时间、持续时长、较上一窗口变化、解除条件、自动失效时间、被暂停动作和不受暂停影响的止损动作。否则 critical 将失去信息价值并产生告警疲劳。

## 9. 报告与窗口一致性

多窗口设计合理，盘前、开盘观察、午间、尾盘和盘后承担不同职责，不应简单合并。

但当前不同窗口反复出现相同的风险边界、大类约束、持仓列表、执行统计、研究论点和轮动候选。Watch Window 应只回答上一窗口结论、本窗口新增变化、原计划是否仍有效、新增动作、被取消动作和下一检查条件；无变化时应 SILENT。

## 10. 报告作为真实交易工具的问题

真实交易者首先需要现在必须做什么、今天不能做什么、哪些只是研究候选、哪些数据不可靠、不操作的风险以及下一次检查条件。当前 Agent Task 同时要求情报、持仓、资金、前瞻、风险和数据质量，容易形成分析百科而非执行面板。

Shadow Account 已累计数百条建议，但没有执行记录。系统无法知道用户是否执行、执行多少、成交价格、为什么拒绝、哪类建议持续被忽略。大量建议、零执行应触发产品级异常，而不是继续增加建议数量。

研究论点追踪应区分新证据、重复引用、反证、已反映在价格中、论点失效和对应交易结果。单纯累计关联次数会制造虚假确定性。

## 11. 多专业视角判决

- 真实交易员：适合作为交易前检查表，不适合作为直接执行单。
- 量化研究员：这是研究框架，不是已验证 Alpha 模型。
- 风险经理：风险识别合格，风险裁决不成熟。
- 资产配置经理：能做跨账户盘点，不能独立做再平衡。
- 投资分析师：情报摘要可用，投资论证不足。
- 产品与运营负责人：系统已具备生产形态，但没有证明用户价值；数百条建议、零执行是最重要的产品信号。

## 12. 风险优先级

### P0：不解决就不应把报告视为可执行建议

- 将资金拆为即时现金、可回收资金和不同到账周期
- 将新鲜度改为按市场和持仓计算
- 数据异常先于交易规则，异常指标必须阻断动作
- 组合约束、风险状态和资产动作形成最终裁决，不只列冲突
- 修正 `trend_confirm_days` 和 `add_ladder` 的实现或命名
- 恢复默认测试全绿并增加核心决策回归测试
- 将今日执行动作和研究候选彻底分离

### P1：不解决就无法证明系统长期价值

- 对 Action Card、因子覆盖和 Capital Allocation 做 Walk-forward
- 加入交易成本、申赎延迟、最小交易单位
- 区分核心仓、战术仓、对冲仓和锁定仓
- 为情报信号增加来源与 synthesized 标记
- Watch Window 改为 Delta，无变化 SILENT
- Critical 增加状态生命周期
- 记录执行、部分执行、拒绝与原因
- Capital Allocation 不得修改原始 Action Card
- Driver、Conflict、Dissent 统一匹配结果

### P2：成熟化方向

- 组合相关性和风险预算
- FX 风险独立建模
- 论点证据去重和反证机制
- Bucket 内部质量排序
- 运行健康检查
- 大文件职责拆分
- CI、类型检查和原子持久化统一

## 13. 目标报告结构

每个交易窗口报告应压缩为五部分：

1. 本窗口变化：与上一窗口相比发生了什么、数据与风险级别是否变化、哪条计划失效
2. 今日动作：标的、动作、数量或金额、最晚执行时间、原因、不执行风险、撤销条件、置信度
3. 禁止动作：暂停加仓、不追高、不因过期数据执行、不对特定资产套用短线规则
4. 组合影响：执行前后比例、真实现金、到账时间、约束变化
5. 下一检查点：时间、价格、事件和数据更新条件

研究、情报和历史统计放入附件或折叠段，不应挡住行动结论。

## 14. 最终验收判决

- 风险监控上线：有条件通过
- 研究与情报辅助：通过
- 持仓事实盘点：通过
- 盘前检查清单：有条件通过
- 自动生成交易动作：不通过
- 组合资金部署：不通过
- 可直接照单执行的报告：不通过
- 量化策略有效性：尚未证明
- 自动交易准备度：不通过

最终定位：stocks-claw 当前像一个勤奋、知识面广、会列出所有风险的初级投资分析师。它能发现很多问题，但还不能像成熟交易员或基金经理一样，在冲突信息中做出唯一、可执行、组合一致并能事后负责的最终决策。

下一阶段开发中心应从多采集、多字段、多建议切换为少而准的动作、明确的组合裁决、真实执行反馈、可复现的收益归因和窗口之间只报告变化。

## 15. 后续验收门

系统只有同时通过以下五道门，才可升级为可信赖的个人交易决策系统：

1. 一致性门：数据、信号、动作、资产、组合、风险六层无未裁决冲突
2. 执行门：报告动作可被记录为执行、部分执行、拒绝或延后
3. 归因门：最终 Action Card 和 Capital Allocation 有版本化效果归因
4. 打扰门：Watch Window 无变化 SILENT，critical 有生命周期
5. 用户价值门：用户连续真实使用后确认报告减少了决策成本并改善了纪律
